# Contributing to claude-md-templates

## What We Accept

We're looking for:

- **New templates** for specific domains (SaaS, data science, content, etc.)
- **Improved examples** based on what you've learned
- **Documentation** for patterns you've discovered
- **Bug fixes** and clarity improvements

## Template Format

Each template should:

1. **Be lean** – Under 150 lines (templates, not essays)
2. **Have a clear purpose** – Stated in first comment
3. **Include sections**:
   - Context (what is this for?)
   - Key decision rules or patterns
   - Important paths/tools
   - When uncertain (guidance)
4. **Be standalone** – Works without reading other templates first
5. **Have examples** – If applicable, show real usage

## Submission Process

1. Create a fork
2. Add your template file (e.g., `project-saas.md`)
3. Update `README.md` to list your new template
4. Submit a PR with a brief description

## Example PR Description

```
Add: project-saas.md template

This template covers:
- Multi-tenant architecture patterns
- API rate limiting guidelines
- Customer data isolation rules
- Common SaaS-specific gotchas

Useful for teams building SaaS products with subscription models.
```

## Review Criteria

- Is it useful for others, not just your project?
- Does it follow the lean template format?
- Are sections clear and actionable?
- Does it avoid being too prescriptive?

## Questions?

Open an issue or start a discussion. We're building this together.
